# Public-page analytics

Status: wired but disabled. A fresh, independent PostHog project key has not been supplied. Set `NEXT_PUBLIC_POSTHOG_KEY` to that new project's public ingestion key and redeploy when ready. Never copy another application's key. This implementation uses PostHog US Cloud (`https://us.i.posthog.com`). No key means no SDK initialization or analytics network requests.

Why this implementation is deliberately narrow: the application has bearer-link directories and email preference links. Ordinary automatic analytics could capture their URLs, referrers, form data or identity. The only allowed routes are the exact static paths `/`, `/events`, `/about`, `/privacy`. Event-detail routes are intentionally excluded, along with every admin, settings, preference, directory and API route.

`components/public-analytics.tsx` is mounted through providers. It explicitly captures one pageview after public-route navigation. Its internal marker distinguishes those calls from automatic SDK activity. `before_send` drops every other event and reconstructs the outbound payload from a strict allowlist. Only the public project token, a random per-page identifier, allowlisted pathname, disabled-person-profile flag and disabled-geolocation flag remain. SDK-added URLs, query/hash, referrer, UTM, auth identity, user/profile fields and nested form data are discarded. There is no call to identify, alias, group or set person properties.

Autocapture, pageleave, replay, errors, dead clicks, heatmaps, performance capture, surveys, product tours, remote dependencies and feature-flag/config requests are disabled. Persistence is disabled; random identifiers are not stable across pageviews. Do Not Track is respected. Fetch uses `referrerPolicy: no-referrer`, and beacon transport is disabled. Network transport necessarily exposes the connection to the analytics provider; IP/geolocation processing is disabled in the SDK settings and event payload. This is pageview counting, not user tracking or funnel analysis.

The configuration follows [PostHog's official JavaScript configuration documentation](https://posthog.com/docs/libraries/js/config) and the installed SDK types/source. Installed `posthog-js` 1.395.0 forwards the supplied fetch options and applies `before_send` before enqueue/send. `advanced_disable_flags` also prevents the remote-config loader from requesting external configuration. Keep those behaviors in mind when upgrading.
